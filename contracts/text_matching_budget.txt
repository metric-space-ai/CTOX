# Wo CTOX noch Entscheidungen aus Fehlertext liest — und wie viel davon.
#
# Gezählt werden Produktionszeilen, die ALLE drei Eigenschaften haben:
#   1. eine Kontrollfluss-Entscheidung (if/while/&&/matches!/filter/any/return),
#   2. `.contains("…")` mit einem String-Literal (keine Mengenabfrage, kein char),
#   3. einen fehler-/statusartigen EMPFÄNGER links von `.contains(`.
#
# Die Zahl ist eine RATSCHE: sie darf nur fallen. Der Guard in
# src/core/text_matching_tests.rs schlägt in beide Richtungen an — eine zu hoch
# stehende Zahl ist genauso rot wie eine überschrittene.
#
# Warum das eine Schuldklasse ist: eine Entscheidung, die aus Prosa gelesen
# wird, ändert sich still, wenn jemand die Prosa umformuliert. ST3 hat genau
# das beseitigt — dort entschied `contains(" completed.") && contains("changed ")`
# über den Terminalstatus einer Queue-Aufgabe.
#
# GRENZE DIESES WÄCHTERS, ehrlich benannt: Punkt 3 prüft den NAMEN des
# Empfängers. `err.contains("timeout")` wird gezählt, `lower.contains("timeout")`
# nicht — obwohl `lower` dieselbe Fehlermeldung sein kann. Eine Umbenennung
# entzieht eine Zeile also der Zählung. Der Wächter fängt damit den Zuwachs an
# der offensichtlichen Stelle, nicht jede Umgehung. Das ist bewusst so: eine
# breitere Regel traf hier Mengenabfragen und Pfadprüfungen mit und wäre
# innerhalb einer Woche mit Ausnahmen durchlöchert worden.
#
# NICHT jede gezählte Zeile ist ein Defekt. Wo ein Fremdwerkzeug seinen Fehler
# nur als Text meldet, ist der Textabgleich die einzige verfügbare Information.
# Solche Zeilen bleiben, sollen aber sichtbar bleiben.
