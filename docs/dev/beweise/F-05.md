# F-05 — Wie viele Modul-Collections binden eine leere Tabelle, waehrend die Daten in einer hoeheren Version liegen?

Du bist ein Leaf-Worker. Keine Subagenten. Antworte auf Deutsch.
**Du aenderst KEINE Datei und fuehrst KEINEN Schreibbefehl auf einer Datenbank aus.
Nur SELECT, nur lesen.** Der Store enthaelt Echtdaten des Nutzers.

## Was bereits belegt ist (nicht wiederholen)

Sellify: 238.913 CRM-Zeilen liegen in `__v1`, alle Manifeste deklarieren
`version 0`, die Peer-Registrierung bindet damit die leeren `__v0`-Tabellen.
Ursache: eine abgeschlossene v0→v1-Migration vom 11.07., deren Deklaration
danach wieder auf 0 zurueckfiel. Der Aufraeum-Sweep
(`repair_stale_rxdb_collection_schema_versions`, `rxdb_peer.rs:14596`) und
`expected_rxdb_collection_version` (`:14562`) iterieren ausschliesslich
`business_os_collections()` — den Contract. Laufzeit-installierte Module sind
darin nicht enthalten und werden nie abgeglichen.

## Deine Aufgabe — eine vollstaendige Bestandsaufnahme

Der Store ist `~/.local/state/ctox/business-os-rxdb.sqlite3` (2,2 GB;
`~/.local/lib/ctox/current/runtime/` ist ein Symlink auf dasselbe Verzeichnis).
Tabellen heissen `ctox_business_os__<collection>__v<version>`.

1. **Liste jede Collection, die in mehr als einer Version existiert.** Fuer jede:
   Name, alle vorhandenen Versionen, `COUNT(*)` je Version.
2. **Bestimme fuer jede davon die heute deklarierte Version.** Quellen sind die
   Manifeste unter `~/.local/state/ctox/business-os/installed-modules/*/collections.schema.json`
   und `~/.local/lib/ctox/current/runtime/business-os/installed-modules/*/`
   sowie der Contract `business_os_schema_contract.json` fuer Kern-Collections.
   Sage bei jeder ausdruecklich, ob sie aus dem Contract oder aus einem
   Laufzeitmodul stammt.
3. **Markiere die Faelle, in denen die deklarierte Version eine LEERE Tabelle
   trifft, waehrend eine andere Version dieser Collection Zeilen haelt.** Das ist
   die eigentliche Frage: wie gross ist der Schaden ausserhalb von Sellify?
   Gib je Fall die Zeilenzahl an, die dadurch unerreichbar ist.
4. **Gegenprobe:** liste auch die Faelle, in denen mehrere Versionen existieren,
   die Deklaration aber die gefuellte Tabelle trifft — damit klar wird, dass
   Mehrfachversionen fuer sich noch kein Defekt sind.
5. **Summe:** wie viele Collections und wie viele Zeilen sind insgesamt
   unerreichbar? Nenne die Zahl ausdruecklich, auch wenn sie null ist.
